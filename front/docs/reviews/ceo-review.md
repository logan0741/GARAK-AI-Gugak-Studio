# GUKAK STUDIO CEO 리뷰

대상 문서: `docs/product/gukak-studio-proposal.md`

작성일: 2026-06-02

## 핵심 판정

**SELECTIVE EXPANSION**

현재 기획서는 30초 가야금 코어 루프, 공공데이터 활용 레이어 분리, 5분 데모 시나리오, 3주 로드맵이 강하다. 다만 심사 관점에서는 "기술적으로 만들 수 있다"는 설득은 비교적 선명한 반면, "누가 왜 써보고 싶어 하며, 첫 MVP에서 무엇을 검증할 것인가"가 아직 약하다. 제품 범위를 늘리기보다, MVP 범위 안에 사용자/시장 검증 계획을 붙이는 선택적 보강이 맞다.

## CEO 관점 주요 Findings

### 1. 사용자 세그먼트가 넓게 열려 있어 첫 검증 대상이 흐릿하다

문서는 대중, 초보자, 숙련자, 창작자, K-Culture 소비자를 모두 암시하지만 MVP에서 누구의 반응을 먼저 볼지 정하지 않는다. 심사위원은 이 제품이 국악 전공자용인지, 일반 음악 앱 유저용인지, 교육 현장용인지 물을 가능성이 높다. MVP에서는 "모바일 음악 앱을 써본 10~20대 비전공자"와 "국악/음악 교육자"를 분리해 검증해야 한다.

### 2. 시장성 주장이 제품 완성도 주장에 묻혀 있다

경쟁자 표는 범용 DAW, 악기 시뮬레이터, 국악 교육 앱과의 차이를 잘 잡고 있다. 하지만 아직 "기존 대안의 사용자 불만"과 "GUKAK STUDIO가 해결하는 반복 사용 동기"가 충분히 증명되지 않는다. 30초 체험이 신기함에서 끝나는지, 녹음/장단까지 이어지는지 검증 지표가 필요하다.

### 3. 심사 설득력은 데이터 활용보다 검증 구조에서 갈린다

공공데이터를 직접 에셋, 분석 참조, 검증 기준으로 나눈 판단은 좋다. 다만 심사에서는 "데이터를 썼다"보다 "데이터 덕분에 무엇을 더 정확히 만들고 검증했는가"가 중요하다. 데모 인스펙터 UI와 함께 음색, 장단, 출처, 검증 기준을 보여주되, 이것이 사용자 가치와 연결되는 문장이 필요하다.

### 4. 3주 로드맵이 기술 검증 중심이라 사용자 검증 게이트가 빠져 있다

현재 로드맵은 오디오 엔진, 터치 모델, 장단 시퀀싱을 잘 쪼갠다. 하지만 매주 누구에게 보여주고 어떤 기준으로 계속/중단/축소 판단을 할지 없다. CEO 관점에서는 Day 5 엔진 픽스만큼 "첫 사용자 5명 테스트", "30초 반응률", "녹음 전환률" 같은 제품 검증 게이트가 필요하다.

## 문서 보강 방향

메인 기획서에는 새 기능을 추가하기보다 `10. 3주 프로토타입 로드맵` 앞이나 뒤에 아래 섹션을 추가하는 것이 좋다. 이 섹션은 심사위원에게 "기술 데모가 아니라 검증 가능한 MVP"라는 인상을 준다.

## 추가 섹션 초안: 사용자/시장 검증 계획

### 사용자/시장 검증 계획

GUKAK STUDIO의 MVP 검증 목표는 전체 시장 규모를 과장해 증명하는 것이 아니라, 첫 30초 가야금 코어 루프가 실제 사용자에게 "국악을 직접 만지는 경험"으로 받아들여지는지 확인하는 것이다. 따라서 3주 프로토타입 기간에는 기능 확장보다 사용자 반응, 반복 사용 의사, 교육/창작 활용 가능성을 작게 검증한다.

#### 1차 검증 대상

| 대상군 | 검증 이유 | 확인할 질문 |
| --- | --- | --- |
| 모바일 음악 앱 또는 리듬 게임을 써본 10~20대 비전공자 | 국악에 전문 지식이 없어도 첫 30초 체험이 직관적으로 통하는지 확인 | 설명 없이 현을 터치했을 때 악기처럼 느끼는가, 30초 이상 탐색하는가 |
| 국악 또는 음악 교육자 3~5명 | 교육 현장에서 실제 악기 접근성 부족을 보완할 수 있는지 확인 | 수업 도입용 체험 도구로 쓸 수 있는가, 어떤 주법/장단 표현이 최소 필요인가 |
| 국악 전공자 또는 가야금 연주자 2~3명 | 전통 악기의 핵심 감각을 훼손하지 않는지 검증 | 농현, 추성, 퇴성, 지음 표현이 과장되거나 어색하지 않은가 |

#### 검증 가설

1. 비전공자는 설명 없이도 한 현 탭, 스와이프, 홀드 드래그를 통해 30초 안에 "버튼음이 아니라 현을 만지는 느낌"을 구분할 수 있다.
2. 사용자는 30초 코어 루프 이후 짧은 선율 녹음 또는 장단 반주 중 하나의 다음 행동으로 자연스럽게 이동한다.
3. 교육자는 정규 커리큘럼 전체보다 "악기 접근이 어려운 상황에서 가야금의 소리와 주법을 먼저 체험시키는 도구"로 가치를 판단한다.
4. 국악 전공자는 완전한 실악기 대체가 아니라, 모바일 제스처로 핵심 주법을 압축한 시뮬레이터라는 포지션을 수용할 수 있다.

#### 3주 검증 게이트

| 시점 | 제품 산출물 | 사용자 검증 | 통과 기준 |
| --- | --- | --- | --- |
| 1주차 말 | 12현 더미 UI와 오디오/터치 스파이크 | 내부 3명 + 비전공자 3명에게 무설명 30초 터치 테스트 | 사용자가 30초 안에 탭, 스와이프, 홀드 드래그 중 2개 이상을 자발적으로 시도 |
| 2주차 말 | 30초 가야금 코어 루프 | 비전공자 5명, 국악/음악 교육자 2명 테스트 | 비전공자 70% 이상이 "악기처럼 느껴진다"고 응답, 교육자 1명 이상이 수업 도입 가능성을 인정 |
| 3주차 말 | 녹음, 장단 프리셋, 데이터 증명 UI가 포함된 5분 데모 | 비전공자 5명, 교육자 3명, 국악 전공자 2명 테스트 | 첫 체험 후 50% 이상이 짧은 녹음 또는 장단 반주까지 진행, 전공자 피드백에서 치명적 왜곡 지적 없음 |

#### 측정 지표

| 지표 | 측정 방법 | MVP 판단 기준 |
| --- | --- | --- |
| 30초 체류율 | 앱 시작 후 30초 이상 직접 조작한 사용자 비율 | 80% 이상 |
| 자발적 제스처 수 | 안내 없이 탭, 스와이프, 홀드, 지음 중 시도한 제스처 수 | 평균 2개 이상 |
| 악기다움 인식 | "버튼음/효과음"이 아니라 "현악기/가야금"으로 느꼈는지 5점 척도 | 평균 4점 이상 |
| 다음 행동 전환 | 30초 코어 루프 후 녹음 또는 장단 반주를 실행한 비율 | 50% 이상 |
| 교육 활용 의사 | 교육자가 수업 도입 또는 체험 활동에 사용할 의향 | 3명 중 2명 이상 긍정 |

#### 검증 후 의사결정

- 30초 코어 루프가 통과 기준을 넘으면 녹음, 장단 반주, 데이터 증명 UI를 데모 범위로 유지한다.
- 악기다움 인식이 낮으면 장단/스튜디오 기능을 늘리지 않고 샘플 품질, 지연, 농현/지음 제스처를 먼저 수정한다.
- 교육자 반응은 좋지만 비전공자 반응이 약하면 제품 포지션을 "대중 창작 앱"보다 "국악 체험/교육 도구" 쪽으로 좁힌다.
- 비전공자 반응은 좋지만 전공자 피드백에서 왜곡이 크면 데모 문구를 "실악기 대체"가 아니라 "가야금 핵심 조작을 압축한 모바일 시뮬레이터"로 명확히 제한한다.

## 심사 Q&A 방어용 3문장

1. "이 프로젝트의 시장 검증은 큰 시장 규모를 주장하는 방식이 아니라, 첫 30초 안에 비전공자가 가야금의 현 조작감을 악기처럼 인식하는지를 실제 사용자 테스트로 확인하는 방식입니다."
2. "공공데이터는 원본 음원을 단순 탑재하는 재료가 아니라, 로컬 샘플 에셋, 음색/장단 분석 참조, 전통성 검증 기준으로 분리해 활용하므로 권리와 품질 리스크를 동시에 관리합니다."
3. "MVP의 AI 요소는 생성형 오디오를 무리하게 붙이는 것이 아니라, 사용자의 터치 이벤트를 분석해 장단 프리셋을 추천하고 로컬 시퀀서로 재생하는 저지연 구조입니다."

## 심사 설득력 보강 메모

- 발표에서는 30초 체험을 먼저 보여주고, 그 다음 "이 반응을 어떻게 검증할 것인가"를 말해야 한다.
- 데이터 활용 설명은 출처 나열보다 "출처가 사용자 경험의 어떤 품질 기준으로 바뀌었는가"에 집중해야 한다.
- 공모전 제출 문서에는 "검증 대상 n명"과 "통과 기준"을 넣는 편이 좋다. 수치가 작아도 MVP 심사에서는 실행 가능성이 더 중요하다.
- "국악 대중화"는 너무 큰 문장이다. MVP 문장으로는 "국악에 관심은 있지만 악기를 접하기 어려운 사용자가 모바일에서 첫 연주 경험을 얻는다"가 더 방어 가능하다.
