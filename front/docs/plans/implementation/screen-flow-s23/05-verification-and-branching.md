관련 문서: `README.md`, `../../../system/conventions.md`, `../../../qa/`

## 브랜치

현재 구현 계획 브랜치는 `codex/plan-s23-screen-implementation`이다. 구현은 같은 브랜치에서 이어간다. 커밋은 팀원이 변경 범위를 알 수 있도록 작은 단위로 나눈다.

권장 커밋 단위:

- `docs: 화면 흐름 구현 계획 분리 작성`
- `test: 화면 흐름 전이 기준 추가`
- `feat: GARAK 화면 흐름 셸 추가`
- `test: 작업 보관함 모델 기준 추가`
- `feat: 작업 보관함 모델 추가`
- `feat: 자유창작 화면 흐름 연결`
- `feat: 따라하기와 공유 설정 흐름 연결`
- `docs: 화면 구조 구현 보고서 작성`

## 자동 검증

실기기 검증을 제외하고 다음 명령을 통과시킨다.

```bash
npm test
npm run typecheck
```

작업 디렉터리:

```bash
front
```

## 테스트 작성 순서

1. `screenFlowMachine.test.ts`에서 라우팅과 제외 화면 규칙을 먼저 실패시킨다.
2. `studioLibrary.test.ts`에서 작업 자동 저장, 내보내기, 보관함 분리를 먼저 실패시킨다.
3. 최소 구현으로 테스트를 통과시킨다.
4. 화면 컴포넌트를 연결한 뒤 `typecheck`로 UI 타입 오류를 검증한다.

## 수동 검증

웹 또는 Expo 개발 서버에서 다음 흐름을 확인한다.

- 홈 자유창작 -> 악기 선택 -> 기본값 시작 -> 자유연주 -> 완료 -> 트랙/레이어 편집
- 트랙/레이어 편집 -> 트랙 추가 -> 악기 연주 추가 -> 적용 -> 트랙/레이어 편집
- 트랙/레이어 편집 -> 트랙 추가 -> 장단/반주 추가 -> 반주 트랙 추가 -> 트랙/레이어 편집
- 홈 따라하기 -> 민요 선택 -> 악기 선택 -> 따라하기 연주 -> 결과 -> 공유 준비
- 홈 보관함 -> 작업 열기 -> 트랙/레이어 편집
- 홈 마이/설정 -> 로그인하고 내 곡 불러오기 -> 로그인/동기화

## 제외 검증

다음 항목은 이번 구현 완료 기준에 넣지 않는다.

- 실제 공공 음원 다운로드
- 실제 오디오 인코딩
- 실제 OS 공유 시트 연동
- 실제 로그인 제공자 연동
- 실제 커뮤니티 피드 백엔드 연동
- 실기기 오디오 지연 검증

## 완료 기준

- S01-S23 화면 흐름 중 제외 화면을 제외한 모든 화면이 앱 안에서 도달 가능하다.
- 주요 CTA가 문서의 다음 화면 연결과 일치한다.
- 자동 저장된 작업과 공유 가능한 산출물이 구분된다.
- 테스트와 타입체크가 통과한다.
- 팀 보고용 문서가 화면 구조 중심으로 작성된다.
