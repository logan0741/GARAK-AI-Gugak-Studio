## 1. 문제 정의

### 수동적 감상 이탈 경험

대중은 유튜브, 틱톡 등의 미디어를 통해 국악 콘텐츠를 소비하지만, 대부분 짧은 감상 후 이탈하는 일회성 소비에 그치고 있다. 국악에 대한 호기심을 능동적인 연주와 창작 경험으로 연결할 매개체가 부족하다.

### 서양 악기 중심 시뮬레이터의 한계

GarageBand, Real Guitar 등 기존 글로벌 모바일 악기 앱은 피아노의 건반, 기타의 프렛처럼 서양 악기의 발음 구조를 중심으로 설계되어 있다. 이 구조에서는 줄을 뜯고, 누르고, 흔들고, 여운을 끊는 가야금 고유의 농현, 추성, 퇴성, 지음 등을 모바일 터치 제스처로 표현하는 데 한계가 있다.

GUKAK STUDIO는 이 지점에서 출발한다. 국악을 설명하거나 감상하게 하는 앱이 아니라, 모바일 화면에서 실제 국악기를 만지는 듯한 감각을 제공하는 국악 악기 시뮬레이터를 목표로 한다.

## 2. 제품 정의

GUKAK STUDIO는 공공 국악 데이터를 단순 재생하지 않고, 가야금의 소리와 터치 규격으로 변환해 누구나 직접 연주하고 합주할 수 있게 만든 모바일 국악 악기이자 가상 스튜디오다.

### 핵심 가치

| 항목 | 내용 |
| --- | --- |
| 악기 접근성 해소 | 실제 가야금을 구하거나 배울 기회가 없어도 모바일에서 가야금의 형태, 음색, 터치감을 직접 체험 |
| 악기다운 터치 경험 | 단순 버튼음이 아니라 현 발음, 잔향 중첩, 농현, 글리산도, 지음 등 가야금의 핵심 조작감을 모바일 제스처로 구현 |
| 창작 확장성 | 시뮬레이터에서 연주한 결과를 녹음하고 장구 장단, 멀티트랙, 반주 추천으로 확장 |
| 참여형 K-Culture 확산 | 국악을 감상하는 콘텐츠에서 직접 연주하고 공유하는 참여형 문화 경험으로 전환 |

### 제품 포지션

GUKAK STUDIO의 1차 정체성은 국악 악기 시뮬레이터다. 스튜디오 기능은 이 시뮬레이터 위에 녹음, 멀티트랙, 장단 반주, 공유를 얹는 확장이다.

## 3. MVP 핵심 경험: 30초 가야금 코어 루프

GUKAK STUDIO의 성패는 기능 개수보다 사용자가 앱을 켜고 첫 30초 안에 "이건 버튼음이 아니라 가야금 현을 만지는 경험"이라고 느끼는 데 달려 있다. 이를 위해 다음 코어 루프를 MVP의 최우선 품질 기준으로 삼는다.

| 시간 | 사용자 경험 | 기술 요구사항 |
| --- | --- | --- |
| 0~5초 | 한 현을 가볍게 뜯어 자연스러운 잔향 확인 | 샘플별 자연 감쇠 유지, 과도한 컷오프 방지 |
| 5~15초 | 여러 현을 쓸어내리며 개방현의 잔향 중첩 체감 | Polyphonic playback, 최소 8개 이상 동시 보이스 안정 재생 |
| 15~25초 | 터치를 유지한 채 손가락을 움직여 농현, 추성, 퇴성 표현 | 홀드 드래그 기반 실시간 pitch bend, 클릭 노이즈 없는 음고 변화 |
| 25~30초 | 울림이 남은 현을 덮어 지음으로 여운 차단 | 롱프레스, 두 손가락, 넓은 면적 터치 기반 release 감쇠 |

이 코어 루프가 안정적으로 구현될 때 녹음, 장단 반주 추천, 멀티트랙 확장이 의미를 갖는다.

## 4. 인터랙션 설계

별도의 주법 선택 버튼을 배제하고, 현을 터치하고 움직이는 연속 제스처만으로 연주를 제어한다. 실제 가야금의 양손 역할을 모바일 환경에서는 하나의 현 중심 제스처로 압축한다.

| 실제 가야금 주법 | 모바일 터치 모델 매핑 | 기술적 작동 메커니즘 |
| --- | --- | --- |
| 오른손 뜯기 / 튕기기 | 현 영역 탭 또는 스와이프 | 즉시 발음 트리거 |
| 왼손 농현 | 발음 후 터치 유지 상태에서 같은 현 주변을 미세하게 반복 이동 | 실시간 미세 주파수 변조 |
| 추성 / 퇴성 | 발음 후 터치 유지 상태에서 현 기준 방향으로 이동 | 드래그 방향과 거리 기반 음고 상승 및 하강 |
| 오른손 / 손바닥 지음 | 롱프레스, 두 손가락, 넓은 면적 터치 | 오디오 엔벨로프 release 값 감쇠 |
| 재발음 | 이미 울리는 현을 짧게 다시 탭 | 같은 현의 새 발음 트리거 |
| 연음 / 글리산도 | 여러 현을 가로질러 연속 스와이프 | 터치 좌표가 지나는 현들의 순차적 독립 발음 |

### 설계 원칙

- 하나의 현을 하나의 독립적인 인터랙션 오브젝트로 취급한다.
- 양손의 공간적 분리를 터치 지속 시간과 움직임으로 치환한다.
- 기능 버튼보다 실제 줄을 만지는 듯한 연속 제스처를 우선한다.
- 초보자와 숙련자는 같은 악기 엔진을 사용하되, 가이드 레이어만 선택적으로 제공한다.

## 5. 공공데이터 활용 구조

저지연 연주성 확보와 원본 재배포 리스크 관리를 위해 데이터의 권리 구조와 품질 조건에 따라 활용 레이어를 분리한다.

본 프로젝트는 특정 공공데이터를 원본 그대로 앱에 탑재하는 방식에 의존하지 않는다. 데이터의 권리 조건과 품질에 따라 직접 에셋, 분석 참조, 검증 기준으로 활용 레이어를 분리해 MVP 구현 가능성을 유지한다.

### 에셋 레이어: 로컬 구동

`국립국악원_국악디지털음원` API 등 공공누리 제1유형 자료에서 활용 가능한 음원 후보를 확보한다. 단음 샘플로 적합한 구간이 확인되는 경우 전처리하여 앱 내 재생 에셋으로 활용하고, 부족한 음역대나 품질이 불충분한 구간은 권리와 품질이 검증된 자체 보완 샘플로 구성한다.

### 분석 레이어: 설계 가이드

AI Hub `국악 악보 및 음원 데이터`는 원본을 앱에 내장하지 않는다. 대신 개발 단계에서 전통 가야금의 음고, 음색, 시김새, 엔벨로프, 장단 특성을 분석하는 참조 기준으로 활용해 사운드 엔진의 규격을 튜닝한다.

### 데이터 활용 요약

| 레이어 | 활용 데이터 | 시뮬레이터 내 역할 |
| --- | --- | --- |
| 에셋 | 국립국악원 국악디지털음원, 자체 보완 샘플 | 로컬 샘플러의 재생용 오디오 에셋 |
| 분석 | AI Hub 국악 악보 및 음원 데이터 | 음고, 음색, 엔벨로프, 시김새 분석 참조 |
| UX | 공공 악보, MIDI, JSON, 장단 라벨 | 따라치기 노트 이벤트 및 장단 추천 기준 |
| 검증 | 공공 음원 및 악보 데이터 | 앱 내 사운드가 전통 가야금 특성과 부합하는지 확인 |

### 주요 출처

- [국립국악원_국악디지털음원](https://www.data.go.kr/data/15097515/openapi.do)
- [AI Hub 국악 악보 및 음원 데이터](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71470)

## 6. AI/장단 반주 MVP

생성형 오디오 모델 도입 시 발생할 수 있는 음질 저하, 레이턴시, 서버 비용, 권리 리스크를 줄이기 위해 MVP에서는 분석 및 로컬 시퀀싱 구조로 범위를 좁힌다.

### 기능명

AI 기반 장단 반주 추천 및 자동 시퀀싱

### 실제 MVP 메커니즘

1. 사용자의 가야금 연주 이벤트를 수집한다.
2. 터치 간격을 기반으로 BPM을 추정한다.
3. 단위 시간당 터치 횟수로 연주 밀도를 계산한다.
4. BPM과 밀도를 바탕으로 중모리, 굿거리, 자진모리 등 장단 프리셋을 추천한다.
5. 추천된 장단 코드를 로컬 장구 단음 에셋과 시퀀서로 즉시 재생한다.

### 예시 매칭

| 입력 조건 | 추천 장단 |
| --- | --- |
| BPM 60~80, 낮은 밀도 | 중모리 |
| BPM 80~110, 중간 밀도 | 굿거리 |
| BPM 120 이상, 높은 밀도 | 자진모리 |

### 고도화 계획

음고 분석을 통한 평조/계면조 선법 기반 반주 추천은 MVP 이후 공공 악보·음원 데이터의 참조 기준을 바탕으로 확장한다.

## 7. 오디오/데이터 플로우 아키텍처

MVP의 연주 경로는 네트워크를 타지 않는 로컬 경로로 고정한다. 공공데이터 API와 분석 데이터는 앱 실행 중 실시간 호출 대상이 아니라, 개발 단계에서 샘플 매니페스트와 검증 기준을 만드는 입력으로 사용한다.

```text
공공/자체 음원 후보
        |
        v
에셋 전처리
  - 권리 조건 확인
  - 단음/준단음 구간 확인
  - trim / normalize
  - envelope metadata 작성
        |
        v
SampleAssetManifest + local audio files
        |
        v
앱 시작 또는 악기 화면 진입 시 preload
        |
        +----------------------------+
        |                            |
        v                            v
Touch input                    Demo inspector
        |                      source / license / quality
        v
Gesture interpreter
        |
        v
PerformanceEvent stream
        |
        +------------------+--------------------+
        |                  |                    |
        v                  v                    v
Voice scheduler      Session recorder     Jangdan analyzer
        |                  |                    |
        v                  v                    v
Sampler engine       Session JSON         Local jangdan preset
        |                                       |
        +------------------+--------------------+
                           v
                    Audio output
```

### 원칙

- 연주 중 오디오 출력은 로컬 샘플 파일과 로컬 시퀀서만 사용한다.
- 공공데이터 API 실패가 연주 실패로 이어지지 않도록, 앱에는 사전 생성된 매니페스트와 출처 메타데이터를 포함한다.
- 터치 입력은 먼저 `PerformanceEvent`로 정규화한 뒤 오디오, 녹음, 장단 분석, 인스펙터가 같은 이벤트를 읽는다.
- Day 5 이후 선택된 오디오 엔진은 `SamplerEngine` 인터페이스 뒤에 둔다. UI와 세션 저장 로직은 특정 오디오 라이브러리에 직접 의존하지 않는다.
- 오디오 엔진 후보 비교는 기능 존재 여부가 아니라 같은 이벤트 스트림을 넣었을 때의 지연, 동시 보이스, pitch bend, mute 품질로 측정한다.

## 8. 샘플러 및 세션 데이터 모델

MVP는 하나의 이벤트 모델을 중심으로 구성한다. 같은 `PerformanceEvent` 스트림이 실시간 재생, 세션 녹음, 장단 추천, 데모 인스펙터의 공통 입력이어야 한다.

### 핵심 모델

| 모델 | 역할 |
| --- | --- |
| `SampleAsset` | 현별 오디오 파일, 기준 음고, 출처, 라이선스, 품질, 엔벨로프 메타데이터 |
| `StringSpec` | 12현 각각의 인덱스, 개방현 음고, 샘플 에셋, 터치 영역 |
| `PerformanceEvent` | 탭, 글리산도, 농현, 지음, release 등 사용자의 연주 이벤트 |
| `VoiceState` | 현재 울리고 있는 보이스의 현, 샘플, pitch bend, gain, envelope 상태 |
| `Session` | 이벤트 목록, 사용한 에셋 매니페스트 버전, BPM/밀도 추정, 장단 추천 결과 |

### 이벤트 예시

```ts
type PerformanceEvent =
  | { type: 'string_pluck'; tsMs: number; stringIndex: number; velocity: number }
  | { type: 'string_bend'; tsMs: number; stringIndex: number; cents: number }
  | { type: 'string_mute'; tsMs: number; stringIndex: number; strength: number }
  | { type: 'glissando_step'; tsMs: number; stringIndex: number; velocity: number }
  | { type: 'string_release'; tsMs: number; stringIndex: number };
```

### MVP 저장 원칙

- 실시간 연주 중에는 `VoiceState`를 메모리에서 관리한다.
- 세션 녹음은 먼저 `PerformanceEvent[]`를 저장한다. 오디오 파일 캡처는 가능하면 붙이되, 실패해도 이벤트 리플레이는 남아야 한다.
- 장단 추천은 오디오 분석이 아니라 이벤트 간격과 밀도에서 계산한다.
- 데이터 증명 UI는 세션 이벤트와 `SampleAssetManifest`를 읽어 어떤 에셋과 분석 기준이 사용됐는지 보여준다.
- MVP에서는 클라우드 동기화 없이 로컬 JSON 세션으로 충분하다.

## 9. 경쟁자 및 차별화

GUKAK STUDIO는 GarageBand 등 범용 DAW와 기능 개수로 경쟁하지 않는다. 또한 국악 교육 앱처럼 정규 커리큘럼을 제공하는 것도 MVP의 목표가 아니다. 핵심 차별점은 국악기 특화 연주성과 수동 감상 경험의 전환이다.

| 경쟁군 | 우리가 이기는 지점 | 우리가 경쟁하지 않는 지점 |
| --- | --- | --- |
| GarageBand류 음악 제작 앱 | 국악기 특유의 터치, 농현, 장단 표현 | 범용 DAW 기능 전체 및 전문 믹싱 툴 |
| Real Guitar류 악기 시뮬레이터 | 가야금 전용 현 중심 제스처와 국악 음색 | 기타, 피아노 등 서양 악기 범용성 |

## 10. 사용자/시장 검증 계획

GUKAK STUDIO의 MVP 검증 목표는 전체 시장 규모를 과장해 증명하는 것이 아니라, 첫 30초 가야금 코어 루프가 실제 사용자에게 "국악을 직접 만지는 경험"으로 받아들여지는지 확인하는 것이다. 따라서 3주 프로토타입 기간에는 기능 확장보다 사용자 반응, 반복 사용 의사, 교육/창작 활용 가능성을 작게 검증한다.

### 1차 검증 대상

| 대상군 | 검증 이유 | 확인할 질문 |
| --- | --- | --- |
| 모바일 음악 앱 또는 리듬 게임을 써본 10~20대 비전공자 | 국악 전문 지식이 없어도 첫 30초 체험이 직관적으로 통하는지 확인 | 설명 없이 현을 터치했을 때 악기처럼 느끼는가, 30초 이상 탐색하는가 |
| 국악 또는 음악 교육자 3~5명 | 교육 현장에서 실제 악기 접근성 부족을 보완할 수 있는지 확인 | 수업 도입용 체험 도구로 쓸 수 있는가, 어떤 주법/장단 표현이 최소 필요인가 |
| 국악 전공자 또는 가야금 연주자 2~3명 | 전통 악기의 핵심 감각을 훼손하지 않는지 검증 | 농현, 추성, 퇴성, 지음 표현이 과장되거나 어색하지 않은가 |

### 검증 가설

1. 비전공자는 설명 없이도 한 현 탭, 스와이프, 홀드 드래그를 통해 30초 안에 버튼음이 아니라 현을 만지는 느낌을 구분할 수 있다.
2. 사용자는 30초 코어 루프 이후 짧은 선율 녹음 또는 장단 반주 중 하나의 다음 행동으로 자연스럽게 이동한다.
3. 교육자는 정규 커리큘럼 전체보다 악기 접근이 어려운 상황에서 가야금의 소리와 주법을 먼저 체험시키는 도구로 가치를 판단한다.
4. 국악 전공자는 완전한 실악기 대체가 아니라, 모바일 제스처로 핵심 주법을 압축한 시뮬레이터라는 포지션을 수용할 수 있다.

### 3주 검증 게이트

| 시점 | 제품 산출물 | 사용자 검증 | 통과 기준 |
| --- | --- | --- | --- |
| 1주차 말 | 12현 더미 UI와 오디오/터치 스파이크 | 내부 3명 + 비전공자 3명에게 무설명 30초 터치 테스트 | 사용자가 30초 안에 탭, 스와이프, 홀드 드래그 중 2개 이상을 자발적으로 시도 |
| 2주차 말 | 30초 가야금 코어 루프 | 비전공자 5명, 국악/음악 교육자 2명 테스트 | 비전공자 70% 이상이 악기처럼 느껴진다고 응답, 교육자 1명 이상이 수업 도입 가능성을 인정 |
| 3주차 말 | 녹음, 장단 프리셋, 데이터 증명 UI가 포함된 5분 데모 | 비전공자 5명, 교육자 3명, 국악 전공자 2명 테스트 | 첫 체험 후 50% 이상이 짧은 녹음 또는 장단 반주까지 진행, 전공자 피드백에서 치명적 왜곡 지적 없음 |

### 측정 지표

| 지표 | 측정 방법 | MVP 판단 기준 |
| --- | --- | --- |
| 30초 체류율 | 앱 시작 후 30초 이상 직접 조작한 사용자 비율 | 80% 이상 |
| 자발적 제스처 수 | 안내 없이 탭, 스와이프, 홀드, 지음 중 시도한 제스처 수 | 평균 2개 이상 |
| 악기다움 인식 | 버튼음/효과음이 아니라 현악기/가야금으로 느꼈는지 5점 척도 | 평균 4점 이상 |
| 다음 행동 전환 | 30초 코어 루프 후 녹음 또는 장단 반주를 실행한 비율 | 50% 이상 |
| 교육 활용 의사 | 교육자가 수업 도입 또는 체험 활동에 사용할 의향 | 3명 중 2명 이상 긍정 |

### 검증 후 의사결정

- 30초 코어 루프가 통과 기준을 넘으면 녹음, 장단 반주, 데이터 증명 UI를 데모 범위로 유지한다.
- 악기다움 인식이 낮으면 장단/스튜디오 기능을 늘리지 않고 샘플 품질, 지연, 농현/지음 제스처를 먼저 수정한다.
- 교육자 반응은 좋지만 비전공자 반응이 약하면 제품 포지션을 대중 창작 앱보다 국악 체험/교육 도구 쪽으로 좁힌다.
- 비전공자 반응은 좋지만 전공자 피드백에서 왜곡이 크면 데모 문구를 실악기 대체가 아니라 가야금 핵심 조작을 압축한 모바일 시뮬레이터로 명확히 제한한다.

## 11. 리스크 관리

### 데이터 수급 리스크

`국립국악원_국악디지털음원` API에서 단음 분리가 어렵거나 앱 에셋으로 쓰기 부적합한 경우, 직접 탑재 비중을 낮추고 재생 에셋은 권리와 품질이 검증된 자체 녹음 샘플로 선회한다. 이 경우에도 공공데이터는 전통 음색과 장단 특성을 분석하는 참조 기준으로 유지된다.

| 판정 | 조건 | 대응 |
| --- | --- | --- |
| A | 12현 엔진에 쓸 수 있는 단음 또는 준단음 샘플 확보 가능 | 공공데이터 직접 에셋 활용 + 분석 참조 병행 |
| B | 가야금 음원은 있으나 합주, 연음, 잔향으로 직접 에셋화 부적합 | 자체 샘플 에셋 구성 + 공공데이터 분석 참조 |
| C | 권리 또는 접근 조건상 직접 탑재 불가 | 자체 샘플 에셋 구성 + 공공데이터 검증 기준 활용 |

### 실패 모드 및 fallback

MVP는 오디오 품질 실패가 전체 데모 실패로 번지지 않도록 Day 5에 명시적인 fallback 결정을 내린다.

| 실패 모드 | 감지 기준 | fallback | MVP 판정 |
| --- | --- | --- | --- |
| 공공 음원이 단음 샘플로 부적합 | 어택이 겹치거나 잔향/합주가 분리되지 않음 | 자체 보완 샘플을 재생 에셋으로 사용하고 공공데이터는 분석/검증 참조로 유지 | 진행 |
| 오디오 엔진 후보가 8보이스 또는 pitch bend를 통과하지 못함 | Day 5 기준에서 끊김, 클릭 노이즈, 50ms 초과 발생 | 다른 엔진으로 전환하거나 재생 엔진과 녹음 엔진을 분리 | 진행 가능 |
| 어떤 엔진도 30초 코어 루프를 통과하지 못함 | 탭, 글리산도, bend, mute 중 2개 이상 핵심 제스처 실패 | Week 3 확장 전부 중단. 1주 추가 스파이크 또는 MVP no-go 판정 | 중단 |
| 샘플 preload가 느리거나 메모리 사용량이 높음 | 앱 시작 지연, 중간 로딩, 재생 시 파일 로드 발생 | 12현 필수 샘플만 preload, 고급 변형 샘플 제외, mono/압축 샘플 사용 | 진행 |
| 녹음 권한 거부 또는 캡처 실패 | 마이크 권한 없음, 네이티브 캡처 실패, 파일 저장 실패 | 오디오 파일 대신 이벤트 세션 저장 및 리플레이 제공 | 진행 |
| 출력 장치 변경 | Bluetooth/헤드폰 연결 변경 후 오디오 중단 또는 지연 급증 | 연주 일시정지, 출력 장치 변경 안내, 세션 이벤트 보존 | 진행 |
| 장단 추천이 부정확함 | BPM/밀도 추정이 데모 입력과 맞지 않음 | 추천을 자동 확정하지 않고 상위 1개 프리셋을 데모 추천으로 표시 | 진행 |
| 데이터 API 또는 외부 출처 접근 실패 | 개발/발표 중 네트워크 불가 | 사전 생성된 매니페스트와 출처 메타데이터로 데모 진행 | 진행 |

## 13. 3주 프로토타입 로드맵

에뮬레이터 환경은 오디오 연산 및 지연 판정에 부적합하므로, 1주차부터 실제 Android/iOS 기기에서 dev build 환경으로 검증을 수행한다.

### 1주차: 오디오/터치 검증 스파이크

목표: 핵심 기술 스택의 제약 조건 확인 및 오디오 엔진 최종 확정

| 일정 | 작업 |
| --- | --- |
| Day 1 | React Native/Expo dev build 환경 세팅, 12현 가야금 더미 UI 구성 |
| Day 2 | 오디오 후보 A `expo-audio`로 재생/녹음 기본기 확인 |
| Day 3 | 오디오 후보 B `react-native-audio-api`로 polyphony, pitch bend, filter 가능성 확인 |
| Day 4 | 터치 모델 검증: 탭, 스와이프, 홀드 드래그, 지음 제스처 매핑 |
| Day 5 | 정량 통과 기준을 비교 검증하여 최종 오디오 엔진 결정 |

#### Day 5 엔진 픽스 통과 기준

| 검증 항목 | 통과 기준 |
| --- | --- |
| 터치-발음 지연 | 실제 기기 기준 체감 지연 없음, 목표 50ms 이하 |
| Polyphony | 최소 8개 이상 동시 보이스 재생 시 음 끊김 없음 |
| Pitch Bend | 홀드 드래그 제스처 중 끊김이나 클릭 노이즈 없이 부드러운 음고 변화 발생 |
| Glissando | 연속적인 현 스와이프 시 입력 누락 없이 모든 현의 개방현 발음 트리거 |
| Mute | 지음 제스처 입력 시 과도한 팝 노이즈 없이 자연스러운 감쇠 곡선 생성 |
| 녹음 가능성 | 네이티브 레벨에서 10초 이상의 실시간 연주 오디오 캡처 및 자체 재생 가능성 확인 |

### 2주차: 30초 코어 루프 구현

목표: 권리와 품질이 확인된 로컬 샘플 에셋을 기반으로, 네트워크 의존 없이 30초 코어 루프를 실제 기기에서 안정적으로 구현한다.

- 12현 독립 발음
- 개방현 잔향 중첩
- 스와이프 글리산도
- 홀드 드래그 기반 농현, 추성, 퇴성
- 지음 제스처
- 데모용 레이턴시 로그
- 오디오 인스펙터 패널 뼈대

### 3주차: 스튜디오 확장 데모

## 14. 결론

GUKAK STUDIO는 국악 데이터를 단순히 감상하거나 재생하는 앱이 아니다. 공공데이터를 가야금의 음색, 조작, 장단의 참조 기준으로 변환하고, 모바일 환경에서 실제로 연주 가능한 국악 악기 시뮬레이터로 구현하는 프로젝트다.

MVP의 핵심은 많은 기능이 아니라 첫 30초의 악기다움이다. 한 현을 뜯고, 여러 현의 잔향을 겹치고, 농현으로 음을 흔들고, 지음으로 여운을 끊는 경험이 설득될 때, 녹음과 장단 반주, 멀티트랙, 공유 기능은 자연스럽게 국악 창작 스튜디오로 확장된다.
