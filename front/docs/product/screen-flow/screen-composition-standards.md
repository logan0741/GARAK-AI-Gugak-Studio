# GARAK 화면 구성 기준

상태: 현재 기준
작성일: 2026-06-18
문서 책임: S01-S23 화면 구조를 구현할 때 따라야 하는 정보 위계, 상태, 여정, 접근성 기준을 정의한다.

관련 문서: `current-screen-flow.md`, `../garak-product-brief.md`, `changes/`

이 문서는 화면의 목적과 연결을 반복하지 않는다. 화면별 CTA와 데이터 흐름은 `current-screen-flow.md`를 따른다.

## 1. 화면 묶음

| 묶음 | 화면 | 1차 목적 |
| --- | --- | --- |
| 진입 / 준비 | S01, S02, S03, S04, S04A | 로그인 없이 흐름 선택, 악기 선택, 기본값 확인 |
| 자유창작 | S05, S07, S08, S09, S10A, S10B | 연주, 작업 자동 저장, 트랙/레이어 편집, 장단 적용 |

## 2. 정보 위계

### 공통 원칙

1. 사용자가 지금 하는 일을 화면 첫 영역에서 알 수 있어야 한다.
2. 화면당 1차 CTA는 하나만 가장 강하게 보인다.
3. 공유 가능한 결과물과 편집 중인 작업은 시각적으로 구분한다.
4. 설명 문구보다 상태와 액션을 먼저 보여준다.

### 자유창작 위계

```text
S05: 악기 연주면 > 녹음 상태 > 장단/레이어/완료
S07: 작업 타임라인 > 트랙 목록 > 저장/내보내기/추가
S08: 트랙 타입 선택 > 사용 가능/잠금 상태 > 취소
S09: 기존 작업 재생 상태 > 악기 연주면 > 녹음/적용
S10A: 장단 선택 > BPM > 볼륨 > 연주로 돌아가기
S10B: 장단 선택 > BPM > 볼륨 > 반주 트랙 추가
```

### 따라하기 위계

```text
S13: 민요 목록 > 난이도/길이 > 미리듣기/선택
S14: 선택한 민요 > 악기 목록 > 추천 악기 배지
S15: 다음 입력 가이드 > 악기 연주면 > 진행/정확도
S16: 결과 점수 > 핵심 피드백 > 다시 연주/저장/공유
```

### 보관 / 공유 / 계정 위계

```text
S17: 공유 대상 미리보기 > 제목 > 공유/저장만 하기
S18: 최근 작업 > 작업 탭 > 내보낸 음원/결과 탭
S19: 재생 상태 > 결과 메타데이터 > 공유/편집으로 열기
S20: 공유 곡 목록 > 재생/리믹스 > 저장
S21: 공유 곡 플레이어 > 원작자/출처 > 리믹스/저장
S22: 현재 계정 상태 > 로그인하고 내 곡 불러오기 > 언어/보관함 관리
S23: 로그인 상태 > 로컬/계정 보관함 비교 > 동기화 선택
```

## 4. 사용자 여정

| 단계 | 사용자가 하는 일 | 사용자가 느껴야 하는 감각 | 화면이 제공해야 하는 것 |
| --- | --- | --- | --- |
| 첫 진입 | 홈에서 자유창작/따라하기 선택 | 바로 시작할 수 있음 | 로그인 관문 없는 S01 |
| 첫 연주 | 악기 선택 후 녹음 | 실제 악기를 만지는 몰입 | S05 악기 중심 연주면 |
| 작업 편집 | 녹음 후 레이어 확인 | 결과를 잃지 않았다는 신뢰 | S07 자동 저장 상태 |
| 확장 | 악기/장단 트랙 추가 | 내가 곡을 쌓고 있다는 통제감 | S08-S10B의 명확한 추가 흐름 |
| 결과화 | 음원 내보내기 또는 따라하기 결과 확인 | 완성물을 소유함 | S19/S16의 재생과 저장 |
| 공유 | 공유 준비 후 전달 | 실수 없이 공유함 | S17 미리보기와 취소 가능성 |
| 복귀 | 보관함에서 다시 열기 | 계속 이어갈 수 있음 | S18 작업/음원 구분 |

## 5. 반응형 / 접근성 기준

- 1차 목표는 모바일 세로 화면이다.
- 터치 대상은 최소 44px 이상으로 둔다.
- 연주면의 핵심 입력 영역은 하단 시스템 제스처 영역과 겹치지 않는다.
- 텍스트는 화면 폭에 따라 줄바꿈되며, 긴 작업명은 말줄임과 상세 보기로 처리한다.
- 색만으로 상태를 구분하지 않고 텍스트, 아이콘, 위치를 함께 사용한다.
- 녹음 중, 처리 중, 저장됨, 실패 상태는 스크린 리더가 읽을 수 있는 상태 문구를 가진다.
- 웹/데스크톱 미리보기에서는 S07 타임라인을 넓히되, 모바일과 같은 정보 위계를 유지한다.

## 6. AI Slop 방지 기준

- GARAK은 마케팅 랜딩이 아니라 작업 중심 모바일 앱이다.
- 대시보드식 카드 모자이크를 화면 기본 구조로 쓰지 않는다.
- 카드가 필요한 곳은 선택지, 목록 항목, 모달형 도구처럼 카드 자체가 상호작용일 때로 제한한다.
- 장식용 그라디언트, 의미 없는 아이콘 반복, 3열 기능 소개 구성은 쓰지 않는다.
- 화면 문구는 기능 설명보다 현재 상태와 다음 행동을 우선한다.

## 7. 재사용할 기존 기준

- Figma 6/10의 회색 와이어프레임 감각과 큰 단일 카드 중심 구성을 S01/S04 계열에 우선 적용한다.
- `산조-가야금.html`의 현 중심 연주 영역은 가야금 연주면의 참고 자료로 둔다.
- `연주-모달.html`의 녹음, 장단, 레이어 액션은 S05/S09 하단 조작의 참고 자료로 둔다.
- `장단및-반주.html`의 BPM, 장단 선택, 볼륨 구조는 S10A/S10B 공통 컴포넌트 참고 자료로 둔다.

## 8. 범위 제외

- S06, S11, S12는 독립 화면으로 구현하지 않는다.
- DAW 수준의 파형 편집, 피치 보정, 자동 박자 보정은 S07 MVP에서 제외한다.
- 자동 저장된 작업은 직접 공유하지 않는다.
- 실제 커뮤니티 피드와 계정 동기화 백엔드는 준비 상태에 따라 데모/스텁으로 대체할 수 있다.
- 실기기 오디오 품질 검증은 구현 이후 QA 단계에서 따로 수행한다.
