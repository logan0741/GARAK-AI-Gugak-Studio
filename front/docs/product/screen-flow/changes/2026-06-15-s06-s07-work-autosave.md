# 2026-06-15 S06 제거와 작업 자동 저장 결정

상태: 채택

관련 문서: `../current-screen-flow.md`, `../../garak-product-brief.md`

## 결정

- S06 `연주 완료 확인`은 독립 화면으로 만들지 않는다.
- S05에서 녹음을 완료하면 방금 녹음한 테이크를 작업에 자동 저장하고 S07 `트랙/레이어 편집`으로 바로 이동한다.
- 방금 녹음한 연주는 잃지 않도록 자동 저장하지만, 곧바로 완성된 곡이나 공유 가능한 음원으로 취급하지 않는다.
- 자유창작의 기본 관리 단위는 `작업`이다.
- S07은 자동 저장된 작업을 열고, 첫 테이크를 첫 트랙으로 배치한 상태에서 시작한다.
- 작업 저장은 편집 가능한 상태 저장이고, 내보내기는 공유/재생 가능한 음원 생성이다.
- 공유는 작업 자체가 아니라 `내보낸 음원` 기준으로 시작한다.
- 보관함은 `작업`과 `내보낸 음원`을 구분해서 보여줘야 한다.

## 이유

- 자유창작의 핵심 경험은 테이크를 만든 뒤 레이어를 쌓아가는 것이다.
- S06 중간 확인 화면을 두면 첫 테이크 이후 편집 흐름이 끊긴다.
- 사용자는 녹음 결과를 잃지 않아야 하지만, 모든 녹음이 곧바로 완성곡처럼 보이면 보관함과 공유 흐름이 혼란스러워진다.
- 작업과 내보낸 음원을 분리하면 편집 가능한 프로젝트와 공유 가능한 결과물을 명확히 관리할 수 있다.

## 예상되는 단점과 대응

- 자동 저장된 작업이 많이 쌓일 수 있다. 보관함에서 `최근 작업`, `이름 없는 작업`, `내보낸 음원`을 구분해야 한다.
- 사용자가 `저장됨`의 의미를 혼동할 수 있다. UI 문구에서 `작업 저장`과 `음원 내보내기`를 분리한다.
- 원본 테이크와 렌더링 음원을 모두 보관하면 용량이 커질 수 있다. MVP에서는 작업 데이터와 원본 테이크를 우선 저장하고, 음원 파일은 내보내기 시점에 생성한다.
