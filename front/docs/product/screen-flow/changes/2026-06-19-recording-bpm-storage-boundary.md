# 2026-06-19 녹음 전 BPM과 저장 경계 변경

상태: 반영 완료
관련 기준 문서: `../current-screen-flow.md`, `../../garak-product-brief.md`, `../../../domain/README.md`, `../../../architecture/runtime-architecture.md`

## 회의에서 나온 프론트 반영 사항

- 악기 선택 뒤 BPM/박자 선택을 강제하지 않고 바로 자유연주로 진입한다.
- 사용자가 단순 연주를 해보는 동안에는 BPM, 박자, 장단을 묻지 않는다.
- 사용자가 `녹음`을 누르는 직전에 BPM, 박자, 장단을 정한다.
- 녹음 직전 설정값은 테이크와 작업 편집 맥락에 저장해 이후 AI 편곡, 장단 추천, 트랙 정렬에 활용한다.
- S05에서 녹음이 끝났다고 바로 서버에 파일을 보내는 흐름을 기본값으로 두지 않는다.
- 여러 테이크/세션을 S07에서 편집하는 동안에는 로컬 `Work`를 기준으로 삼는다.
- 서버 저장의 1차 후보는 단일 `Session`이 아니라 여러 레이어를 가진 `Work` 또는 그 작업에서 파생된 `ExportedAudio`다.
- `Session` 자체까지 서버에 저장할지, 최종 `Work`/완성 곡만 서버에 저장할지는 백엔드와 확정해야 한다.
- AI 모델 서버가 별도로 생기면 프론트가 보낼 입력 패키지와 받을 출력 타입을 문서화해야 한다.

## 화면 기준 변경

- S04A `연주 기본 설정`에서 BPM, 박자, 장단 항목을 제거한다.
- S05 `악기 자유연주`의 `녹음` CTA는 바로 녹음 시작이 아니라 녹음 전 설정 오버레이를 먼저 연다.
- S05 녹음 전 설정 오버레이는 BPM, 박자, 장단 프리셋, 바로 녹음 시작 CTA를 제공한다.
- S10A `라이브 장단 가이드`와 S10B `반주 트랙 만들기`는 같은 장단/BPM 데이터 소스를 재사용할 수 있지만 화면 책임은 분리한다.
- S07 `작업 저장`은 로컬 보존을 먼저 보장하고, 서버 저장은 별도 동기화 상태로 표현한다.
- S18 `보관함`은 계정/서버 저장이 붙으면 로컬 항목과 서버 동기화 상태를 함께 확인하는 화면이 된다.

## 데이터 / API 확정 필요 사항

- 백엔드가 저장할 최상위 단위: `Session`, `Work`, `ExportedAudio` 중 무엇인지.
- 서버에 오디오 파일을 보낼 트리거: S07 `작업 저장`, S07 `내보내기`, S18 `보관함`, S23 `동기화` 중 어디인지.
- AI 모델 서버 입력: 이벤트 JSON, 오디오 파일, 트랙 묶음, 작업 전체 중 무엇인지.
- AI 모델 서버 출력: 장단 추천, 반주 트랙 후보, 오디오 파일, 분석 리포트 중 무엇인지.
- 서버/API 실패 시 로컬 작업을 어떻게 표시하고 재시도할지.
